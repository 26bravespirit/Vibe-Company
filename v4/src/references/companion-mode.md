# Coaching Hook — 教练即时提示规范

## 概述

Coaching Hook 是嵌入在每个 Mode 执行完成后的教练反思步骤。它不是被动观察——Claude skill 框架不支持被动监控。它是一个**主动检测 + 提示**的机制，在教练输出结果后检查用户的行为模式并给出简短建议。

## 执行时机

每个 Mode（0-6）执行完毕、输出结果后，**自动运行** Coaching Hook。

## 检测规则

### 规则1：全盘接受检测

**条件：** 用户在本次会话中连续 3 轮以上未对 AI 输出提出任何修改、质疑或选择。
表现为：
- 连续说 "好的"、"可以"、"就这样"、"OK"
- 未对选项做出选择（默认接受第一个）
- 未要求 AI 从不同角度分析

**提示（新手版）：** "试试让AI从不同角度挑战你的方案——好的想法经得住反驳。你可以说：'从反面来看，这个方案有什么问题？'"

**提示（入门版）：** "你已经连续几轮没有挑战AI的输出了。试试T06（让AI挑毛病）或T11（换个角度看）。"

**提示（熟练/专家版）：** "Ownership check: 3+ rounds without pushback. Consider T06/T11/T12."

### 规则2：缺少验证检测

**条件：** 用户表达交付意图（"最终版"、"发给老板"、"可以用了"、"done"）但在本次会话中从未做过一致性检查或验证步骤。

**提示（新手版）：** "交付前花30秒让AI检查全文逻辑一致性——这是最值得的30秒。你可以说：'检查一下全文有没有矛盾的地方。'"

**提示（入门版）：** "你还没做交付前验证。试试T16（交付前验证）：让AI检查全文一致性。"

**提示（熟练/专家版）：** "Pre-delivery: T16 verification not run. Also consider T17 if supporting docs exist."

### 规则3：重复打转检测

**条件：** 用户在同一部分（同一章节、同一段落、同一概念）进行了 3 次以上修改，但修改之间没有实质性方向变化（不是越来越好，是在反复调整）。

**提示（新手版）：** "如果微调解决不了，试试换个角度——有时需要推倒重来而不是修修补补。你可以说：'如果从零开始，这部分应该怎么写？'"

**提示（入门版）：** "你在这个部分已经改了3次了。考虑T08（版本跳跃）——也许需要换一种写法而不是继续微调。"

**提示（熟练/专家版）：** "Iteration stall detected. T08 version leap or Navigate (Mode 4) may unblock."

### 规则4：格式先行检测

**条件：** 用户在内容尚未稳定时（仍在修改核心内容）就要求 AI 进行格式化、美化、排版。

**提示（新手版）：** "先把内容做对，再管它长什么样——内容和格式分开做效率更高。等内容定了再说排版。"

**提示（入门版）：** "T05建议：内容与格式分离。先确认内容OK，再做格式化。"

**提示（熟练/专家版）：** "T05: Content not stable yet. Separate content from format."

## 提示频率控制

| 成长阶段 | 频率 |
|---------|------|
| 新手 | 每次 Mode 执行后都检测并提示 |
| 入门 | 每次检测，但只在检测到问题时提示 |
| 熟练 | 仅在检测到严重模式时提示（全盘接受 5+ 轮，或交付无验证） |
| 专家 | 仅在用户主动要求时提示（"帮我检查习惯"） |

## 提示风格

- **新手：** 用完整的中文句子，给出具体的示范话术（"你可以说：'...'"）
- **入门：** 使用技巧直觉名 + 简短建议
- **熟练/专家：** 使用技巧编号 + 一句话提示
- **所有阶段：** 提示最多2句话，不打断工作流

## 与 Persistence Layer 的交互

Coaching Hook 的检测结果会写入日志的 `anti_patterns` 字段：
- 全盘接受 → `"Acceptance Loop"`
- 缺少验证 → `"No Verification"`
- 重复打转 → `"Perfectionism Spiral"`
- 格式先行 → `"Format Fixation"`

这些数据支持 Mode 1 (Review) 的长期趋势分析——识别用户反复出现的坏习惯。
